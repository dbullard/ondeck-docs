## What Preview features are

Starting with Relay `1.3.0`, the beta and release versions of Relay are **one app with one update feed**. The newer work that used to ship only in beta builds now lives behind a switch: **Preview features**.

Preview features are early or evolving parts of Relay that are available for testing before they're considered stable for every user and every production environment. They may change faster than the rest of the app and can have rough edges or missing workflows. Preview features are **off by default**.

<Warning>
  Do not assume a Preview feature is ready for a mission-critical show just because it appears in the app. Test it in your actual workflow first.
</Warning>

## Turn Preview features on or off

1. Open `Relay > Settings` → <Icon icon="test-tubes" /> **Preview**.
2. Turn **Enable preview features** on or off.
3. Quit and reopen Relay. The change takes effect after a restart.

<Note>
  If you were on the beta before Relay `1.3.0`, turn on **Enable preview features** after updating and restart Relay to keep using what you had.
</Note>

## What Preview features include

- **Newer automation triggers**, such as the ProPresenter State trigger
- **Smart light control**, with [Smart Lights](/relay/integrations/lighting) and [Vista](/relay/integrations/vista) automation destinations
- **Extra DAW Transport protocols**, such as Logic Pro, Reaper, and Cubase/Nuendo, beyond the default ones
- **Newer device models**, including Shure `ANX4`, `ADTD`, and `ADTQ` receivers and certain audio console models
- **Wireless Diagnostics Logging** controls in the Preview settings page

Some modules also carry a **Beta** badge in the module catalog even when Preview features are off. These are working but still being refined: [YouTube Live Stream Monitor](/relay/integrations/youtube-live), [NDI Feed](/relay/integrations/ndi), [Sennheiser](/relay/integrations/wireless-devices#sennheiser-workflows), and [Shure Overview](/relay/dashboards/modules/wireless#shure-overview-beta).

<Note>
  The standalone **Shure** module and **Live Transcription** are stable and don't need Preview features.
</Note>

## What happens if I turn Preview features off

Turning Preview features off hides the preview-only tools above. Your saved DAW Transport protocol is kept, so turning Preview back on restores it. Dashboards that already use a preview-only feature keep their saved settings.

## Preview tools in Settings

When Preview features are on, the **Preview** page also shows **Wireless Diagnostics Logging**: verbose logging toggles for Shure and Sennheiser device families, each with a "Reset Defaults" button. Verbose wireless tracing is only active when Preview features are on, after a restart.

<Note>
  To export logs or copy a diagnostic summary, use `Relay > Settings` → <Icon icon="circle-help" /> **Help**. For feedback on a Preview feature, email `support@ondeckapps.com`.
</Note>

## Text module behavior to test carefully

The text module stores rich formatting inside the attributed content itself, while still decoding older legacy formatting fields for backward compatibility. Rendering paths differ between macOS rich-text display, standard text rendering, and LAN snapshot rendering (what a Mirror or browser view-only viewer sees). If you rely on text-heavy tiles — lyrics, notes, operator instructions — verify that formatting survives saving and reopening the dashboard, that older dashboards still render as expected, and that a mirrored or browser view stays close enough to the editable view.

## Graph runtime behavior to test carefully

Time triggers poll and fire based on in-memory runtime state, and wireless trigger conditions rely on live device state and cooldown behavior. Trigger firing order is deterministic, but still worth validating in real-world chains, especially when an automation controls consoles, wireless destinations, or other downstream production systems. When testing automation-heavy workflows, validate cooldown timing, repeated-trigger behavior, disconnect edge cases, action ordering, and whether reopening the dashboard changes behavior in subtle ways.

## When to use Preview features

Preview features are a good fit when you want early access to a capability the team is still refining, you can test it ahead of a live event, and you're comfortable giving feedback when something feels unclear.

They're a poor fit when the workflow is business-critical and cannot fail, there's no time to test before going live, or the feature sits in the middle of a complex automation or routing chain that would be hard to recover from quickly.

## A safe testing workflow

1. Test it on a non-critical dashboard first.
2. Keep the rest of the dashboard simple while evaluating it.
3. Verify its behavior in both Canvas View and Live Mode if relevant.
4. Test with the real device, service, or data source it will depend on.
5. Have a fallback plan before using it in production.

<Tip>
  The safest way to roll out a Preview feature is to isolate it. One new variable at a time is much easier to evaluate than a whole chain of new behavior.
</Tip>

## Troubleshooting

### A Preview feature behaves inconsistently

Check whether the feature depends on another connection, permission, or service, and whether the behavior is repeatable on demand or only occasional.

### A Preview feature is missing entirely

Check that **Enable preview features** is on under `Relay > Settings` → <Icon icon="test-tubes" /> **Preview** and that you restarted Relay afterward. Some features also only appear when the required hardware or integration is present, such as Shure `ANX4` models or Sennheiser devices.

### I found an issue

Document what you expected to happen, what actually happened, exact reproduction steps, whether it happens every time or only sometimes, and any screenshots, logs, or diagnostics — then send it to `support@ondeckapps.com`.
